## 1. 需求描述

### 用户原话

> 需求就是shared所有需求

### 我的理解

本仓（lab-management-system-fastapi）把 lab 家族 shared 契约（lab-management-system-shared，
TypeSpec SSOT）定义的**全部业务面**实现到与家族既有后端（springboot / aspnetcore / rails）
功能对等：`docs/functions/function-tree.md` 全部 7 模块 26 功能从「规划」逐批转为「已上线」，
生成骨架里所有端点从「未实现 500 兜底」变为真实现。

口径（2026-09-29 用户三项拍板，saas 仓镜像 REQ 同批立档）：

1. **范围**：saas + lab 双 fastapi 仓都做（本仓为 lab 侧镜像，saas 仓另立 REQ）。
2. **REQ 形态**：本文件是**总纲**——只立范围、验收与分批计划；实现按批次拆后续
   `/req` 逐批进门（届时才拆 I 级子项 + red-first 补测试）。
3. **验收口径**：家族 contract-test 收录 fastapi target，live 模式对本仓全部断言绿。

## 6. 风险与回滚

| 风险 | 影响面 | 缓解 | 回滚方式 |
|---|---|---|---|
| python-fastapi 生成器为官方 beta，升级可能破产物模板 | 生成区 | 7.24.0 钉版（openapitools.json），升级走 ADR | git revert 生成区 commit |
| contract-test 尚无 fastapi target | AC-1 | 批6 专项接入；接入前各批以本仓 L4 + AC-4 端点对照为过渡验收 | target 开关独立，不影响既有四后端断言 |
| M03 过程流是状态机（7 环节跨 5 功能） | 批5 | 家族参照实现（springboot/aspnetcore/rails 已全绿）+ flow-function-map.md 双参照 | 批内按环节小步提交，可退回任一环节 |
| 体量大（26 功能）跨多会话 | 账本一致性 | 每批独立 /req + 独立验收 + session.json 交接 | 批次间互不阻塞，任一批可独立回退 |
| 实现手改生成区抄近路 | 硬规则 §4 | 生成区 regen 先删后写 + 幂等门 strict（AC-3） | regen 即抹掉手改，漂移必红 |
